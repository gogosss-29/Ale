EMPECEMOS POR LO OBVIO ●

Un LLM solo es un cerebro en un frasco

Un modelo de lenguaje, por sí mismo, solo hace una cosa: recibe texto → predice texto.

  • No puede leer tus archivos
  • No puede correr un comando
  • No puede instalar nada ni probar su propio código
  • No recuerda nada entre conversaciones

Es brillante razonando… pero no tiene manos. Es un genio atrapado en una caja de chat.

🧠

Modelo puro

texto entra → texto sale

cero acceso al mundo real

La pregunta del millón:
¿cómo le damos manos al cerebro?

Slide 2 · El problema 0:01 – 0:04

  • Punto clave: la gente cree que la magia está en el modelo. La magia de verdad está en lo que envuelve al modelo.
  • Analogía: ChatGPT en la web = cerebro en un frasco. Te da texto y tú haces todo el trabajo manual (copiar, pegar, ejecutar, verificar).
  • Transición: lo que le da manos al cerebro tiene un nombre técnico → el arnés.

0:07 – 0:11 · Anatomía

EL CORAZÓN DEL ARNÉS ●

El Agent Loop · 3 fases

1

Gather context

Lee archivos, busca en el repo, consulta MCP. Entiende antes de tocar.

→
2

Take action

Escribe código, corre comandos, edita archivos. Usa las manos.

→
3

Verify

Lint, compila, corre tests. ¿Funcionó? Si no → vuelve al paso 1.

El loop se repite solo hasta cumplir el objetivo o agotar el límite de turnos. Eso es la autonomía: no es que el modelo sea más listo — es que el arnés lo deja intentar, fallar y corregir sin ti.

Slide 5 · Agent Loop 0:07 – 0:11

  • El paso 3, verify, es el que casi nadie implementa bien y es el más importante. Un agente que no verifica su trabajo alucina con confianza.
  • Claude Code verifica con typecheck/build/tests. Conecta esto con el "Auto-Blindaje" de Forge más adelante (error → fix → documentar → nunca repetir).
  • Mensaje: la autonomía no es magia del modelo, es el LOOP del arnés. Mismo modelo sin loop = chatbot.
0:11 – 0:15 · Claude Code

EL PRIMER ARNÉS REAL ●

Claude Code = un arnés de fábrica

Cuando abres claude en tu terminal, no estás hablando con un modelo. Estás manejando un arnés completo que Anthropic ya armó por ti:

  • Bash tool → corre lo que sea
  • Filesystem → lee/escribe tu repo
  • Sandbox + permisos → te pide aprobar acciones
  • Agent loop → gather → act → verify
  • Skills + MCP → extensible sin tocar el core

No genera código y ya.
Opera dentro de un arnés que le da autonomía.

# Esto NO es un chatbot.
# Es un arnés corriendo en tu repo.
$ claude

> "Arregla el bug del login y
   corre los tests"

# El arnés solo:
  1. lee src/features/auth/**
  2. edita el archivo roto
  3. corre npm test
  4. ve que pasa → done ✓

Slide 6 · Claude Code 0:11 – 0:15

  • Esta es la slide "aha": lo que usan a diario ES un arnés. Llevan semanas usando uno sin saber el nombre.
  • Mapear cada pieza de la slide anterior 1-a-1 con Claude Code refuerza que la teoría es real.
  • Por eso Claude Code se considera "el primer agente real de coding" — no por el modelo, por el arnés alrededor.
0:15 – 0:19 · Agent SDK

EL ARNÉS, AHORA PROGRAMABLE ●

Claude Agent SDK

El Agent SDK (antes "Claude Code SDK") convierte el arnés en un subproceso que llamas desde código. Claude Code deja de vivir solo en tu terminal.

Lo que te da

  • query() — le pasas el prompt al arnés
  • ClaudeCodeOptions — config: max_turns, cwd, tools…
  • Message — la respuesta son objetos estructurados, no texto plano
  • MCP — engánchalo a Jira, Slack, una base de datos…

Con esto construyes tus propias apps agénticas: backends, bots, interfaces de chat sobre tu código.

# TypeScript
npm i @anthropic-ai/claude-agent-sdk

import { query } from
  "@anthropic-ai/claude-agent-sdk";

for await (const msg of query({
  prompt: "explica este repo",
  options: { cwd: "~/nucleo",
             maxTurns: 8 }
})) {
  render(msg); // stream a la UI
}
# Python — mismo concepto
pip install claude-agent-sdk

Slide 7 · Agent SDK 0:15 – 0:19

  • Frase clave: "Claude Code como librería". El mismo arnés que usas en terminal, pero invocable desde cualquier app.
  • max_turns = cuántas veces el agente puede iterar solo (el loop). Es el dial de autonomía.
  • La respuesta son Message objects (assistant, tool_use, result) — por eso puedes hacer una UI bonita que muestre "está leyendo X", "está corriendo Y".
  • Demo 2 (al final) usa exactamente esto: una web app de chat sobre NÚCLEO.
0:19 – 0:24 · ACP

EL PROTOCOLO QUE CONECTA TODO ●

ACP · Agent Client Protocol

Estándar abierto creado por Zed. Resuelve un problema simple pero enorme:

Sin estándar, cada editor necesita integración custom con cada agente → N × M integraciones y vendor lock-in.

ACP estandariza editor ⇄ agente

JSON-RPC sobre stdio (local) o HTTP/WebSocket (remoto). Reusa las representaciones JSON de MCP.

Un agente que "habla ACP" funciona en cualquier cliente ACP: Zed, y vía adaptadores VS Code, JetBrains, Neovim… o tu propio agente.

Cómo se conecta Claude Code

Cliente ACPZed · editores · tu app
→
@agentclientprotocol/
claude-agent-acpel adapter · JSON-RPC
→
Claude Agent SDKel arnés, programable
→
Claude Codeel arnés trabajando

Slide 8 · ACP 0:19 – 0:24

  • Mensaje clave: ACP es a los agentes lo que USB-C a los cargadores. Un enchufe estándar.
  • La cadena de la derecha es el momento "todo encaja": el adapter @zed-industries/claude-code-acp envuelve el Agent SDK (slide anterior), que maneja Claude Code (el arnés). ACP + SDK + arnés son la misma historia vista en 3 capas.
  • Instalación real: npx @agentclientprotocol/claude-agent-acp (antes @zed-industries/claude-code-acp, ahora renombrado). Es lo que usa Zed por debajo.
  • OJO al nombre: "Agent Client Protocol" (Zed, editor⇄agente). No confundir con "Agent Communication Protocol" (agente⇄agente, otra cosa).
  • Honestidad técnica: Claude Code NO es ACP nativo (no tiene `--acp`). Habla ACP solo vía el adapter — por eso el adapter está en la cadena. El cliente ACP canónico hoy es Zed.
0:24 – 0:25 · 3 vías

CÓMO UN AGENTE MANEJA EL ARNÉS ●

3 formas · de menos a más sofisticada

📦

Print mode

claude -p --output-format json

Batch: manda → espera → recibe JSON. El resultado vuelve por stdout.

lo robusto
🖥️

tmux

teclea con send-keys, lee con capture-pane

Interactivo, pero screen-scraping + sleep a ojo.

cinta adhesiva
🔌

ACP

JSON-RPC · eventos estructurados · bidireccional

Interactivo y limpio. Vía adapter.

el estándar

tmux = la versión con cinta adhesiva de lo que ACP estandariza.
Por eso existe ACP.

Slide 9 · Las 3 vías 0:24 – 0:25

  • Las 3 maneras en que un agente (Hermes, un editor, tu app) puede manejar el arnés Claude Code, de menos a más sofisticada.
  • Print mode: lo que usa mi Hermes hoy (siguiente slide). Fiable, devuelve JSON por stdout. Para delegar ("ve, hazlo, repórtame").
  • tmux: manejar la TUI interactiva como títere — teclas + foto de pantalla. Funciona pero es frágil (timing con sleeps, parsear ANSI).
  • ACP: la versión limpia y estandarizada de eso mismo. El remate: tmux es el parche manual que ACP convierte en protocolo. Por eso ACP importa.

MI AGENTE PERSONAL ●

Hermes · el orquestador de mi Mac Mini

Qué es Hermes

Un agente autónomo que corre 24/7 en mi Mac Mini M4. Lo invoco por Discord (canal #hermes).

Modelo: deepseek-v4-pro vía opencode-go · MCPs: GoHighLevel, Stripe, video.

Es mi router + memoria + monitoreo: ve el CRM, programa crons, vigila pipelines. Lo que NO hace bien: código grande y refactors.

Hermes delega en Claude Code

Cuando una tarea es "código pesado", Hermes no la hace él — lanza Claude Code en print mode y le delega:

# Hermes, internamente
terminal(
  "claude -p 'añade dark mode'
   --output-format json",
  workdir="~/.../nucleo"
)
# → el arnés corre y devuelve JSON
# → Hermes parsea el resultado
# → me avisa por Discord ✓

Hermes = el jefe que delega.
Claude Code = el especialista que ejecuta.

0:33 – 0:39 · Forge

Y AQUÍ ENTRA LO MÍO ●

Forge = un arnés sobre el arnés

Arnés genérico

Claude Code "crudo"

  • Flexibilidad total: Bash + filesystem
  • El modelo descubre cómo resolver
  • Cada proyecto empieza de cero

Genial, pero te pide ser muy bueno guiando herramientas de bajo nivel.

Forge · arnés con método

La Forja sobre Claude Code

  • Comandos de alto nivel: /plan /build /crisol
  • Guards en español: "Blueprint-First", "nunca uses any", "RLS siempre"
  • Skills + Golden Path + memoria git-versioned
  • Auto-Blindaje: error → fix → documenta → nunca repite
  • Multiplataforma: Claude · Codex · OpenCode · Cursor · Gemini

No reemplaza el arnés. Lo doma. Forge convierte el vibe coding en ingeniería repetible.

Slide 12 · Forge 0:33 – 0:39

  • Marco honesto: hay otros frameworks-sobre-arnés (Strands define tools con name/description/input_schema; Ralph descompone un PRD a JSON y lo itera feature por feature). Forge es mi opinión sobre cómo debe ser.
  • La idea de "guards en inglés/español" es literal: en vez de middleware complejo, le escribes al arnés reglas en lenguaje natural que respeta en runtime (ej. "no toques las reglas de eslint").
  • Aquí promociono Forge sin venderlo duro: muestro CLAUDE.md de NÚCLEO con los comandos y reglas. El producto se vende solo cuando ven el orden que impone.

0:39 – 0:41 · Forja

EL HERMANO ENTERPRISE ●

Forja · diseñado para orquestarse con Hermes

Forge

el framework que ya viste

  • Arnés con método para 1 agente (tú + Claude Code)
  • Multiplataforma: Claude · Codex · OpenCode · Cursor · Gemini
  • Paralelismo: solo Fork (worktrees)
  • Tú lo manejas a mano

Forja · Forge Enterprise

getforja/forja

  • Pensado para multi-agente: Coordinator + Fork + Swarm
  • Regla orchestrator-stays-thin → los sub-agentes invocan skills
  • Puente Hermes (opcional): skill el-supervisor + /hermes-bridge
  • Un supervisor externo (Hermes) despacha y vigila la fábrica

Forge = tú manejas el arnés. Forja = un agente (Hermes) orquesta una fábrica de arneses.
Funciona 100% sin Hermes — pero está diseñado para enchufarse a él.

Slide 13 · Forja + Hermes 0:39 – 0:41

  • Aquí cierro el arco: Hermes (slide 10) era el orquestador; Forja es la fábrica diseñada para ser orquestada por un agente como Hermes.
  • Diferencia clave con Forge: Forge es single-agent (tú al volante); Forja añade multi-agente (Coordinator+Fork+Swarm) + un puente para que un supervisor externo despache trabajo.
  • Honestidad: el puente Hermes (el-supervisor + /hermes-bridge) es la arquitectura decidida (ADR D8.4), integración OPCIONAL plug-and-play — Forja corre 100% sin Hermes. Preséntalo como la visión/diseño, no como "ya shippeado".
  • Gancho comercial suave: Forge es el que enseño y uso en clase; Forja es la versión enterprise para fábricas multi-agente.
